# Contributing

Use one packet, one `codex/` branch, and one PR. Keep changes inside the packet's `allowedPaths`, preserve deterministic offline behavior, and add stable negative-vector tests for every new rejection boundary.

Packs are data and documentation only. Do not add scripts, templates, credentials, remote resources, model prompts, executable modes, or provider-specific paid defaults. New dependencies require packet authority, exact offline locks, license review, and a preloaded wheel closure.

Do not claim deployment, runtime, assurance, or tenant acceptance from local validation or packaging evidence.
